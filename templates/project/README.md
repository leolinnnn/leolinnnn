## Repository guide

Use only directories with a real responsibility in this project:

| Location | Responsibility |
| --- | --- |
| Root entry commands | Run the documented workflow |
| `src/` | Reusable computational implementation |
| `data/` | Bundled inputs and a field/units/availability dictionary |
| `reference/` | Archived result and QA comparison targets |
| `assets/` | Figures and screenshots used in documentation |
| `docs/` | Methods, reproduction, validation and research record |
| `tests/` | Meaningful checks of computations or system behaviour |
| `PROVENANCE.md`, `source_manifest.json` | Human-readable source history and machine-readable identities |

Add `configs/`, `models/`, `unreal/`, `examples/` or `legacy/` only when warranted.
Preserve engine-internal asset paths. Generated files go in ignored `outputs/`.
Do not create empty folders or invented data to fill the template.

## Validation and scope

Describe checks actually completed, expected values, tolerances and external
requirements. Identify whether an image is regenerated by this workflow or copied
from a research source. Document consequential limitations next to the claim they
affect. Add CI only for checks that can run on the shared package.

## Research record

Give the actual study title, authors and verified status. Link `CITATION.cff`,
source notes and applicable reuse terms. Repository metadata describes the shared
software/archive; it must not invent a manuscript DOI, acceptance or publication.
